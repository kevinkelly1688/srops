# 常见问题

## 登录与账号

### Q：能用 LDAP、飞书、钉钉等账号登录吗？

不能。平台只支持平台本地账号 + 密码登录，请联系管理员在「用户管理」中为你创建账号。

### Q：密码输错几次后提示“账号已临时锁定”？

连续失败达到「平台设置 → 安全策略 → 登录失败锁定」次数（默认 5 次）后锁定 30 分钟。可等待自动解锁，或请管理员处理。

### Q：忘记密码怎么办？

请管理员在「用户管理」中重置：管理员会看到一个随机生成的新密码（仅显示一次），通过安全渠道告知你，首次登录后须修改。

## 集群导入

### Q：打开页面只看到“欢迎使用”，没有任何数据？

平台还没有导入集群。管理员在引导页点击「导入已有集群」，或在「安装部署」中新建集群。

### Q：所有运维按钮都是灰色的，提示“必填信息未完善”？

该集群导入时没有填写 SSH 凭据和部署目录，目前只能查看。有 `cluster.edit` 权限的用户点击页面顶部提示条的「立即完善 →」补全即可。

### Q：导入时测试连接失败？

确认平台服务器能访问 FE 的 9030 / 8030 端口，运维账号的 host 包含平台 IP，密码正确。

## 权限相关

### Q：按钮是灰色带 🔒，点不了？

你的角色没有该按钮的权限码。鼠标悬停按钮可看到需要的权限名称和权限码（如 `node.restart`），把它告诉管理员即可。也可以在头像菜单「个人信息与权限」里查看自己已有的全部权限。

### Q：左侧找不到某个菜单（例如「安装部署」）？

没有该菜单的“查看”权限（`<页面>:view`）。例如「安装部署」默认只有超级管理员和运维管理员可见，DBA、值班只读、审计员看不到。

### Q：顶栏集群列表里有的集群带 🔒？

你的角色数据范围不包含该集群。

### Q：管理员改了我的权限，我这边没变化？

刷新页面即可生效。

### Q：为什么点了“确认执行”提示“已提交复核”？

平台开启了双人复核，需要另一位有同样权限的同事在「操作审计 → 待复核」中批准。

## 界面与水印

### Q：怎么切换护眼模式？

顶栏右侧或头像菜单中选择「🌿 护眼」。主题保存在本机浏览器，换电脑需重新选择。

### Q：页面上的水印能去掉吗？

水印由超级管理员统一配置，用于截图外泄追溯，普通用户不能关闭；通过浏览器开发者工具删除后也会自动恢复。超级管理员可在「平台设置 → 水印」调整或关闭。

### Q：打印 / 导出 PDF 没有水印？

请在浏览器打印设置中勾选“背景图形”。

## 告警通知

### Q：飞书 / Lark 机器人收不到告警？

依次检查：Webhook 地址是否完整（飞书为 `open.feishu.cn`，Lark 为 `open.larksuite.com`，不能混用）；机器人开启了签名校验时平台是否填写了相同密钥；开启了 IP 白名单时是否加入了平台出口 IP。用「测试」按钮验证。

### Q：Slack 收不到告警？

Incoming Webhook 只能发到创建时绑定的频道；Lark、Slack 为境外服务，平台需要能访问外网（「平台设置 → 基础 → 出网 HTTP 代理」）。

## 运维相关

### Q：BE 下线一直卡在某个进度？

剩余 BE 空间不足或有副本无法迁移（如单副本表、Colocate 组约束）。执行 `SHOW PROC '/backends'` 看 TabletNum 是否在下降，并检查巡检“单副本表”项。

### Q：导入报 too many versions？

Compaction 跟不上导入频率。降低导入频率、增大攒批，必要时调大 Compaction 线程；见「性能巡检 → Compaction」。

### Q：新 FE 启动后一直加入不了？

首次启动必须带 `--helper <leader_ip>:9010`；检查 9010 端口与 FE 之间时钟偏差（< 5 秒）。如果之前用错误方式启动过，需要清空新节点的 `meta` 目录后重来。

### Q：Routine Load 自动暂停了？

在「导入作业」点“错误详情”查看 `ReasonOfStateChanged`，修复后点击“恢复”。

### Q：物化视图变成 INACTIVE？

基表做过 Schema Change。确认物化视图定义仍然有效后，点击“启用”。

### Q：修改的 FE 参数重启后失效了？

`ADMIN SET FRONTEND CONFIG` 与 BE 的 `update_config` 都只改内存。在「参数配置」的修改弹窗里勾选 **同时写入配置文件**（需要 `param.persist` 权限和集群的 SSH 信息），平台会通过 SSH 把参数写进各节点的 `fe.conf` / `be.conf` / `cn.conf`，重启后就不会丢。全局变量用 `SET GLOBAL` 修改，会自动持久化。

### Q：慢查询 / SQL 审计提示“读取审计表失败”？

常见的报错有两种：`Unknown database 'starrocks_audit_db__'`（库不存在，说明集群**没有安装 AuditLoader 插件**），或提示没有权限（平台账号读不了审计表）。这两处读取 `starrocks_audit_db__.starrocks_audit_tbl__`，需要同时满足两个条件：集群已安装 **AuditLoader** 插件，并且平台使用的运维账号对该表有 SELECT 权限。

**先确认原因**，在 StarRocks 里执行：

```
SHOW PLUGINS;
SHOW DATABASES LIKE 'starrocks_audit_db__';
```

- `SHOW PLUGINS` 里没有 AuditLoader，或者没有 `starrocks_audit_db__` 这个库：按下面的步骤安装 AuditLoader；
- 库和表都在，但平台仍然报没有权限：直接看后面的“授权给平台账号”。

**安装 AuditLoader**（依据官方文档 [AuditLoader](https://docs.mirrorship.cn/zh/docs/administration/management/audit_loader/)；建表语句随 StarRocks 版本略有不同，请以官方文档里对应版本的为准）：

1. **建库建表**：先执行 `CREATE DATABASE starrocks_audit_db__;`，再按官方文档创建 `starrocks_audit_db__.starrocks_audit_tbl__`。**不要修改表的属性**，否则日志导入会失败。这张表是按天动态分区的，建好约 10 分钟后才会出现第一个分区，可用 `SHOW PARTITIONS FROM starrocks_audit_db__.starrocks_audit_tbl__;` 查看。
2. **下载并解压插件**：下载 `https://releases.mirrorship.cn/resources/auditloader.zip`，执行 `unzip auditloader.zip`，得到 `auditloader.jar`、`plugin.properties`（不用改）和 `plugin.conf`。
3. **修改 `plugin.conf`**：通常只需要改 `user` 和 `password`，各配置项见下表。
4. **重新打包**：`zip -q -m -r auditloader.zip auditloader.jar plugin.conf plugin.properties`
5. **分发**：把 zip 放到**每台 FE** 的同一个绝对路径下，或者放到所有 FE 都能访问的 HTTP 服务（httpd、nginx 等）上。安装之后这个文件不要删除。
6. **安装**：本地路径用 `INSTALL PLUGIN FROM "<zip 的绝对路径>";`；网络地址用 `INSTALL PLUGIN FROM "http://<地址>/auditloader.zip" PROPERTIES("md5sum" = "<zip 的 md5>");`（网络地址必须带 md5sum）。
7. **验证**：执行 `SHOW PLUGINS\G`，AuditLoader 的 `Status` 应为 `INSTALLED`；随便执行几条 SQL，等约 60 秒后执行 `SELECT * FROM starrocks_audit_db__.starrocks_audit_tbl__ LIMIT 10;`，应该能看到记录。

`plugin.conf` 的配置项：

| 配置项 | 说明 |
|---|---|
| `frontend_host_port` | FE 的 `IP:HTTP 端口`，只支持填一个。默认 `127.0.0.1:8030`，FE 的 HTTP 端口不是 8030 时改成实际端口 |
| `database`、`table` | 审计库名、表名，须与第 1 步建的一致（默认就是 `starrocks_audit_db__` 和 `starrocks_audit_tbl__`） |
| `user`、`password` | 写入审计表的账号，需要对审计表有 INSERT 权限；`secret_key` 为空时 `password` 填明文 |
| `filter` | 可选，按 Stream Load 的 WHERE 条件过滤要写入的记录，默认不过滤 |

装好后一直没有数据：检查 `plugin.conf`（库表名、账号密码、`frontend_host_port`）。修改配置前必须先执行 `UNINSTALL PLUGIN AuditLoader;`，改好后重新打包、安装。插件日志写在 FE 的 `fe.log` 里，搜索关键字 `audit`。

**授权给平台账号**：把下面的 `sr_ops` 换成「集群接入」里填的运维账号：

```
GRANT SELECT ON TABLE starrocks_audit_db__.starrocks_audit_tbl__ TO USER 'sr_ops'@'%';
```

**回到平台**：在「查询分析」页点 **重试** 即可。如果接入集群时没有勾选“已安装 AuditLoader”，性能巡检里的“慢查询数”规则会显示“跳过”，请在「集群接入」中补充。

### Q：终止查询后，客户端为什么还能继续用？

终止的是**查询**（`KILL QUERY`），连接保持。需要断开连接请在 StarRocks 中执行 `KILL <连接 ID>`。

### Q：备份策略为什么没有“保留份数”？

StarRocks 没有删除仓库快照的 SQL 命令。S3 协议的仓库可以在「备份恢复 → 仓库 → 清理设置」配置清理凭据后，由平台删除快照目录，并在备份策略里设置保留策略自动清理（详见「备份恢复」第 5 节）；HDFS 等仓库请在存储上配置生命周期规则或手工清理。

## 节点、部署与升级

### Q：安装包已经在服务器上了（wget 下载的），部署页面选不到？

平台只认登记过的安装包，直接放进 `data/packages/` 不会被识别。把文件放到 `<数据目录>/import/`（或保留在 `packages/` 里），在「安装部署 → 安装包」点「从服务器导入」登记即可；详见「安装部署」的「1.2 安装包」。

### Q：节点管理里“启动 / 停止 / 重启 / 扩容”是灰的？

集群的 SSH 凭据或部署目录没有填写（“待完善”）。有 `cluster.edit` 权限的用户在「集群接入」里补全即可。

### Q：上传安装包提示“文件名不符合要求”？

不要改官网下载的文件名：StarRocks 包须是 `StarRocks-<版本>-<系统>-<amd64|arm64>.tar.gz`，JDK 包须以 `jdk` / `OpenJDK` / `amazon-corretto` / `java` 开头并以 `.tar.gz` 结尾。上传时平台还会检查压缩包内容，缺少 `fe/bin/start_fe.sh`、`be/bin/start_be.sh`（JDK 包缺少 `bin/java`）会拒绝。

### Q：添加主机提示“SSH 指纹与首次记录不一致”？

平台第一次连接主机时记录它的 SSH 指纹，之后指纹变了就拒绝连接，防止中间人。主机重装过的话，确认无误后删除平台数据目录里 `ssh/known_hosts` 中该主机的那一行。

### Q：停止 FE 被拒绝，提示存活的 Leader / Follower 不足多数？

停止后剩下的 Leader + Follower 数量不超过一半，FE 将无法选主。请先恢复其他 FE；确实要操作（例如整套停机）可以勾选 **强制**。

### Q：部署 / 扩容 / 升级中途失败了怎么办？

这些操作都是可重复执行的后台任务：到「部署任务」「操作记录」或「升级回滚」看日志找到原因，修复后点 **重试 / 继续执行**。已经完成的步骤（已上传的安装包、已运行的进程、已加入的节点、已升级的节点）会被跳过。

### Q：升级后想回到旧版本？

在「升级回滚」选中该计划点 **回滚**：平台把每个节点的 `bin` / `lib` 换回升级时备份的 `*.bak-<旧版本>`。前提是备份目录还在，并且升级后没有使用过新版本的新特性。

## 原型说明

### Q：页面数据是真实的吗？

分两种打开方式：

| 打开方式 | 数据 |
|---|---|
| 通过平台服务 `sr-ops` 访问（顶栏显示“● 已连接平台服务”） | **全部页面都是真实数据与真实操作**：集群导入、集群总览、集群架构、性能巡检（含定时巡检通知）、查询分析（含 SQL 审计）、资源隔离、节点管理、安装部署、升级回滚、备份恢复、导入作业、物化视图、参数配置、告警中心、用户管理、角色权限、操作审计、平台设置 |
| 直接双击 `index.html` 或用静态服务器访问（顶栏显示“原型演示”） | 全部为模拟数据，操作不会连接任何集群；刷新页面后数据（包括水印、渠道、平台设置等）恢复初始状态。顶栏“切换用户”下拉框与登录页的“演示账号”仅用于演示权限效果 |

平台服务的部署方法见 [平台部署与集群导入](#help/install)。

### Q：为什么我没有看到某个角色 / 某个用户的编辑按钮，或角色旁边有 🔒？

平台只允许你授予、管理**权限不超过你自己**的角色与用户，避免通过“给自己加角色”提权。需要更高权限的操作，请联系超级管理员。

### Q：设置了 IP 白名单后自己进不去了怎么办？

保存白名单时，平台要求您当前的来源 IP 在名单内，一般不会误锁。如果仍然无法访问（例如换了网络），登录平台所在服务器，通过**本机地址**（`http://127.0.0.1:端口`）访问——本机回环地址始终放行——进入「平台设置 → 安全策略」修改白名单。使用反向代理时，请确认已配置 `-trusted-proxies`，否则来源 IP 是代理地址。

### Q：开启双人复核后，操作为什么没有立即执行？

高危操作（移除集群、删除用户、删除角色等）会进入「操作审计 → 待复核」，需要另一位拥有同样权限的用户批准后才执行；24 小时内无人处理会自动失效，您也可以在批准前撤回。

### Q：用户被“登录失败锁定”了怎么办？

连续输错 5 次密码会临时锁定 30 分钟，到时自动解除。管理员也可以在「用户管理」点该用户的「解锁」立即解除。

### Q：页面一片空白 / 没有样式？

不要把页面内容以 `data:` 地址打开。请直接双击 `index.html`，或启动本地服务后访问 `http://localhost:8766/`。

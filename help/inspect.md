# 性能巡检

性能巡检对集群做一次“全面体检”：按 9 大类、27 项规则检查节点、资源、数据、Compaction、查询、导入、物化视图、配置和操作系统，给出**健康分**、每项的**当前值 / 阈值 / 结论 / 处置建议**和官方文档链接。

## 1. 执行巡检

1. 顶栏选择集群，进入「性能与诊断 → 性能巡检」。
2. 点击 **▶ 立即巡检**（权限 `inspect.run`）。下方实时显示每个分类的检查进度，耗时约 40 秒。
3. 巡检完成后自动刷新结果，并在「巡检历史」生成报告编号 `IR-yyyyMMddHHmm`。

> 巡检只执行只读 SQL、读取 Prometheus 指标和主机只读命令，**不会修改集群**，可在业务高峰执行。

## 2. 读懂结果

### 结果状态

| 状态 | 含义 |
|---|---|
| 正常 / 警告 / 异常 | 按阈值判定 |
| 建议 | 不影响健康分的优化建议（如未配置大查询熔断、未开启查询队列） |
| 跳过 | 前置条件不满足，没有检查：未配置 SSH（系统环境类）、未配置审计表（慢查询）、与集群架构无关（存算分离集群的磁盘、副本类） |
| 采集失败 | 执行 SQL 或读取指标出错（例如该版本没有对应的 information_schema 表），详情中给出错误信息 |

> “跳过”和“采集失败”不扣分，但也**不代表正常**，请按提示补充配置。

### 健康分

满分 100：每个 **异常** 扣 4 分，每个 **警告** 扣 1 分，**建议** 不扣分，被忽略的项不计分。

| 分数 | 结论 |
|---|---|
| ≥ 85 | 健康 |
| 70 – 84 | 需要关注，安排处理 |
| < 70 | 存在风险，优先处理 |

### 巡检分类与典型规则

| 分类 | 典型规则 | 数据来源 |
|---|---|---|
| 节点健康 | FE / BE 存活、FE 元数据同步延迟、Checkpoint、FE JVM 堆 | `SHOW FRONTENDS`、`SHOW BACKENDS`、JVM 指标 |
| 资源水位 | BE 磁盘、内存、CPU | `SHOW BACKENDS`、BE 指标 |
| 数据健康 | 不健康 Tablet、单副本表、分桶大小、副本均衡 | `SHOW PROC '/statistic'`、`information_schema.partitions_meta` |
| Compaction | Compaction Score、最大版本数 | BE 指标 |
| 查询性能 | P99、慢查询数、失败率、大查询熔断配置 | FE 指标、审计日志、资源组 |
| 导入作业 | 暂停的 Routine Load、导入失败率、运行中事务 | `SHOW ROUTINE LOAD`、`information_schema.loads` |
| 物化视图 | 刷新失败、非活跃 MV | `information_schema.materialized_views` |
| 配置合规 | 默认副本数、查询队列、版本一致 | FE 配置、系统变量 |
| 系统环境 | Swap、THP、ulimit、时钟同步 | 主机 SSH 只读命令 |

### 筛选与详情

- 右侧「分类得分」点击分类名即可筛选；明细表头部可按分类、状态筛选。
- **点击任意一行**打开详情：检查方法（SQL / 指标）、处置建议、官方文档链接。

## 3. 常见异常的处理思路

| 巡检项 | 处理 |
|---|---|
| BE 磁盘使用率高 | 到「节点管理」扩容 BE，或清理过期分区（设置动态分区 / TTL）。达到 `storage_flood_stage_usage_percent`（默认 95%）后会拒绝导入。 |
| Compaction Score 过高 | 降低导入频率（攒批），检查磁盘 IO；必要时在「参数配置」调大 `cumulative_compaction_num_threads_per_disk`。 |
| 不健康 Tablet | 通常是节点重启后副本补齐中，持续不降需排查：`ADMIN SHOW REPLICA STATUS FROM tbl`。 |
| 单副本表 | `ALTER TABLE t SET ("replication_num" = "3")`。 |
| Routine Load 暂停 | 到「导入作业」查看错误详情，修复后恢复。 |
| FE JVM 堆过高 | 调大 `fe.conf` 中 `-Xmx`，并检查分区 / Tablet 数量是否过多。 |
| THP 为 always | 在主机执行 `echo madvise > /sys/kernel/mm/transparent_hugepage/enabled` 并写入开机脚本。 |

## 4. 忽略巡检项

对已知且可接受的问题（例如开发集群的单副本表），可点击该行的 **忽略**（权限 `inspect.ignore`），该项不再计入健康分，再次点击“取消忽略”恢复。忽略操作记入审计。

## 5. 导出报告

**⇩ 导出报告**（权限 `inspect.export`）通过浏览器打印为 PDF。巡检历史中的每份报告都可单独导出。

## 6. 定时巡检与规则

「定时与规则」页签：

- **定时巡检**（权限 `inspect.schedule`）：启用 / 停用、执行周期（每天固定时间，或每隔 N 小时）、巡检分类范围、结果通知。
- **巡检规则 / 阈值**（权限 `inspect.rule`）：可修改内置规则的阈值，或新建自定义规则。自定义规则支持三种检查方式：SQL 查询、Prometheus 表达式、主机命令（SSH）。

> 自定义 SQL 规则请只写 `SELECT`；平台使用只读账号执行巡检 SQL。

### 定时巡检结果通知

在「定时巡检 → 编辑」中选择 **结果通知** 方式，定时巡检完成后把结果推送到群机器人：

| 通知方式 | 消息格式 | 签名密钥 |
|---|---|---|
| 企业微信 | Markdown 消息 | 不需要 |
| 钉钉 | Markdown 消息 | 安全设置选「加签」时填写 SEC 开头的密钥；选「自定义关键词」时关键词请包含“巡检” |
| 飞书 / Lark | 消息卡片，标题按结果显示红 / 橙 / 绿 | 机器人开启「签名校验」时填写 |
| Slack | 带颜色条的消息（严重红 / 警告橙 / 正常绿） | 不需要 |
| 邮件 | 纯文本邮件，主题为健康分摘要；收件人最多 20 个，经「平台设置 → 通知」配置的 SMTP 发送 | 不需要 |
| Webhook | JSON（健康分、各状态数量、问题项列表） | 可选；填写后附带请求头 `X-SROps-Timestamp` 与 `X-SROps-Signature: sha256=<HMAC-SHA256(密钥, 时间戳 + "." + 请求体)>` |

- **发送条件**：**仅有问题时**（默认：有异常项，或健康分低于设定值，默认 80 分），或 **每次巡检后**。
- **消息内容**：集群、健康分、报告编号与时间、各状态数量，以及异常 / 警告 / 采集失败的巡检项（每类最多 5 项，已忽略的项不列出）。
- **定时巡检本身失败**（例如集群连不上）时也会发送失败通知。
- **发送测试消息**：用当前填写的配置立即发送一条测试消息（内容为该集群最近一次巡检报告），保存前可先验证。
- **上次通知**：「定时与规则」页显示上次通知的时间与结果；失败时显示原因（如签名错误、地址无效）。每次发送也会记录到操作审计。
- 「平台设置 → 基础」中配置了**平台访问地址**时，消息末尾会带上“查看详情”链接。
- Webhook 地址中带有机器人 token，与签名密钥一样**加密保存**，页面只显示脱敏后的地址；编辑时留空表示保持不变，更换通知方式后须重新填写。
- Lark、Slack 等境外地址需要代理时，在「平台设置 → 基础」配置出网 HTTP 代理（或在服务启动环境中设置 `HTTPS_PROXY`）。

> 定时巡检通知直接发送到这里填写的机器人地址，与「告警中心 → 通知渠道」相互独立。

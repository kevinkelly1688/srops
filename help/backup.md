# 备份恢复

StarRocks 通过 **仓库（Repository）** 把快照备份到远端存储（S3 / OSS / COS / MinIO / HDFS），并从快照恢复。

## 1. 仓库

「仓库」页签，权限 `backup.repo`。列表显示名称、位置、是否只读、Broker、创建时间与状态；**快照列表**按钮读取 `SHOW SNAPSHOT ON <仓库>`，显示快照名与时间戳（恢复时需要）。

- **创建仓库**：
  - S3 / 兼容 S3（OSS、COS、MinIO 等）：位置（`s3a://bucket/path`）、Access Key、Secret Key、Endpoint、Region、是否路径风格访问；
  - HDFS：位置（`hdfs://...`）、Broker 名称（`SHOW BROKER` 中的名称）、用户名 / 密码；
  - 可设为只读仓库（仅用于恢复，例如容灾集群读取主集群的备份）。
- **删除仓库**：只删除仓库映射，不删除远端存储中的快照文件。

> **访问密钥只用于创建仓库的那一条 SQL，平台不保存**；审计日志里密钥只记录为 `***`。

```
CREATE REPOSITORY `repo_s3_prod` WITH BROKER
ON LOCATION "s3a://sr-backup/prod-sr-01"
PROPERTIES ("aws.s3.access_key" = "***", "aws.s3.secret_key" = "***", "aws.s3.endpoint" = "...");
```

## 2. 发起备份

**＋ 发起备份**（`backup.create`）：选择数据库、备份对象（留空为整库，或填写表名，多个用逗号分隔）、快照名和仓库（只读仓库不能用于备份）。

```
BACKUP SNAPSHOT `dws`.`snap_dws_20261006` TO `repo_s3_prod` ON (`fact_order`, `dim_sku`);
```

> 同一数据库同一时间只能有一个备份或恢复作业，平台会在提交前检查并提示；备份期间不能对相关表做 Schema Change。

「备份 / 恢复作业」页签对每个数据库显示**最近一次**备份和恢复作业（`SHOW BACKUP / SHOW RESTORE` 只返回最近一次），状态为 PENDING → SNAPSHOTING → UPLOADING → FINISHED。有作业运行时页面每 4 秒自动刷新，运行中的作业可 **取消**（`backup.cancel`）。

## 3. 恢复数据

**⟲ 从快照恢复**（`backup.restore`，高危，可走双人复核）：

1. 选择仓库，再从该仓库的快照列表中选择快照（时间戳自动带入）；
2. 选择恢复到的数据库；
3. 填写恢复对象，多个用逗号分隔，`表 AS 新表名` 表示恢复为新表。**强烈建议使用 `AS` 恢复为新表**，核对无误后再改名替换，避免覆盖线上表。**留空会恢复快照里的全部表，同名表的数据会被覆盖**；
4. 副本数填 0 表示沿用快照中的副本数；确认 SQL 后输入集群名执行。

```
RESTORE SNAPSHOT `dim`.`snap_dim_20261001` FROM `repo_s3_prod`
ON (`dim_user` AS `dim_user_restore`)
PROPERTIES ("backup_timestamp" = "2026-10-01-02-00-00-123", "replication_num" = "3");
```

## 4. 备份策略

「备份策略」页签（`backup.policy`）：由**平台服务**按周期（每天 / 每周几 + 时间）对所选的每个数据库发起 `BACKUP SNAPSHOT`，快照名为 `auto_<策略ID>_<时间>`。可随时启用 / 停用 / 编辑 / 删除；列表显示下次执行时间、上次执行时间与每个库的执行结果。

- 某个库上已有进行中的备份 / 恢复作业时，该库本次**跳过**并记录原因，不影响其他库；
- 新建、修改或重新启用的策略从**下一个周期**开始执行，不会补跑已错过的时间；平台服务停止期间错过的周期同样不补跑；
- 每次定时备份都写入审计（操作人为“系统（备份策略）”）；
- **旧快照的清理**：见下一节。设置了**保留策略**的策略才会清理旧快照，其他策略不会删除任何快照。

| 推荐策略 | 示例 |
|---|---|
| 核心汇总库 | 每天 02:00 |
| 维表 | 每周日 03:00 |
| 明细库（数据量大） | 在 StarRocks 中按分区备份最近 N 天分区 |

## 5. 清理旧快照

StarRocks **没有删除仓库中快照的 SQL 命令**（`DROP REPOSITORY` 只删除仓库映射，不删除存储里的文件）。平台提供的清理，是通过 S3 协议直接删除快照在对象存储里的目录：

```
<仓库位置>/__starrocks_repository_<仓库名>/__ss_<快照名>/
```

目前支持 **S3 协议的仓库**（`s3` / `s3a` / `oss` / `cos` / `obs` / `tos`，包括 AWS S3、MinIO、阿里云 OSS、腾讯云 COS 等）；HDFS、Azure 等仓库暂不支持，请在存储上自行清理。**删除的是存储里的文件，不可恢复，删除后无法再从这些快照恢复数据。**

### 5.1 配置清理凭据（`backup.clean`）

创建仓库时填写的密钥平台不保存，所以清理需要单独配置：「仓库」页签 → **清理设置**，填写访问端点（如 `https://s3.cn-north-1.amazonaws.com.cn` 或 `http://minio:9000`）、地域（默认 `us-east-1`）、是否路径风格访问（MinIO 等需要）、AccessKey / SecretKey。

- 保存前平台会用该凭据**列出仓库目录**验证连通性和读取权限，失败则不保存；**删除权限在第一次清理时才会检验**。
- 凭据**加密保存**，页面只显示脱敏的 AccessKey；建议使用**只对该仓库目录有读写权限的子账号**。
- 仍有保留策略在使用该仓库时，不能删除凭据。删除仓库时凭据一并删除。

### 5.2 手动删除快照

「仓库 → 快照列表」勾选快照，点击 **删除所选快照**（`backup.clean`，高危，需输入集群名确认，可走双人复核）。清理作为后台任务运行，可以在任务面板查看进度和日志；每个快照的删除结果写入「操作审计」。一次最多 50 个。

### 5.3 保留策略（自动清理）

在备份策略里设置**保留策略**：

| 设置 | 含义 |
|---|---|
| 保留最近 N 份 | 超出最近 N 份的快照可以删除（0 = 不限） |
| 保留 N 天内 | 超过 N 天的快照可以删除（0 = 不限） |

- 两项都设置时，**同时满足**“超出份数”和“超过天数”才会删除；两项都为 0 表示不清理。
- 只处理**该策略自己创建的快照**（名称以 `auto_<策略ID>_` 开头）。手动备份的快照、其他策略的快照永远不会被动到；状态不是 OK 或时间无法识别的快照也不处理。
- **最新的一个快照永远保留。**
- 平台**每小时**对启用中的策略清理一次，**每次最多删除 10 个**最旧的过期快照（过期很多时分几次清完）；停用的策略不清理。结果显示在策略列表的“上次执行”里，并写入审计（操作人为“系统（备份策略）”）。
- 策略列表的 **清理** 按钮先**预览**哪些快照会保留、哪些会删除，确认后可以**立即清理**。
- 设置保留策略前必须先配置该仓库的清理凭据。

### 5.4 安全保护

- 删除范围只限于上述快照目录；快照名必须是普通名称（不含 `/`、`..`），目录前缀必须以 `/` 结尾，不会误删名称相近的其他快照目录。
- 集群上有**进行中的恢复作业**时拒绝清理（恢复可能正在读取仓库里的文件）。
- 同一仓库同一时间只能有一个清理任务。
- 清理完成后平台会重新读取 `SHOW SNAPSHOT` 确认快照已消失；如果仍被列出会在任务日志里提示（可能是对象存储延迟）。

# 告警中心 / 操作审计

## 告警中心

连接平台服务时，告警由**平台每分钟评估一次**：直接读取各集群的总览数据（节点状态、磁盘、Compaction、JVM、延迟、Routine Load、物化视图、Tablet 健康），不依赖 Prometheus；告警、静默、渠道、规则配置都保存在平台服务端。

### 当前告警

| 状态 | 含义 |
|---|---|
| 告警中 | 规则持续触发，未有人处理 |
| 处理中 | 已有人 **认领**（`alert.ack`），显示认领人；**认领后不再重复提醒**，恢复时仍会发恢复通知 |
| 已静默 | 被静默规则屏蔽，不发送通知（仍显示在列表里） |
| 已恢复 | 指标恢复正常，进入“历史”（保留 7 天） |

- 左侧菜单「告警中心」上的红色数字是“告警中”的数量（不含已静默、处理中）；总览页的“活跃告警”卡片显示当前集群的真实告警。
- 同一集群、同一规则、同一对象在持续异常期间只有**一条**告警；级别随取值在警告 / 严重之间变化。
- 对象不存在了（例如节点被移除）按“已恢复”处理；**某次采集失败不会把告警误判为恢复**。平台连续 2 次连不上集群时，产生“集群连接失败”严重告警。
- 数据范围受限的用户只能看到范围内集群的告警，也只能认领范围内集群的告警。

### 告警规则

平台内置 9 条规则，可调整**警告 / 严重阈值、持续时间、通知渠道、启停**（`alert.rule`），对**所有集群**生效（因此需要“全部集群”数据范围的角色），可随时“恢复默认”。阈值含义是“**大于等于**该值”。**暂不支持自定义 PromQL 规则。**

| 规则 | 对象 | 默认警告 / 严重 | 默认持续 |
|---|---|---|---|
| 集群连接失败 | 集群 | — / 发生即告警（连续 2 次采集失败） | 立即 |
| 节点失联 | FE / BE / CN | — / 发生即告警 | 1 分钟 |
| BE 磁盘使用率 | BE | 80% / 85% | 5 分钟 |
| Compaction Score | BE | 50 / 100 | 10 分钟 |
| FE JVM 堆使用率 | FE | 80% / 90% | 5 分钟 |
| 查询 P99 延迟 | 集群 | 3000 ms / 10000 ms | 5 分钟 |
| Routine Load 暂停 | 集群 | 1 个 / 3 个 | 1 分钟 |
| 物化视图刷新失败 | 集群 | 1 个 / 3 个 | 立即 |
| 不健康 Tablet | 集群 | 1 个 / 100 个 | 10 分钟 |

> 持续时间按“连续异常多久才告警”计算，评估粒度为 1 分钟；平台服务重启后重新开始计时。

### 自定义规则（PromQL）

内置规则不够用时，在「告警规则」页签下方的**自定义规则**里用 PromQL 描述任意指标（需要 `alert.rule` 与“全部集群”数据范围；最多 50 条）：

1. 点击 **＋ 新建自定义规则**，填写名称和 **PromQL 表达式**，选择**适用集群**（默认所有配置了 Prometheus 的集群）。
2. 点击 **在所选集群上试运行**：平台向该集群的 Prometheus 执行一次即时查询，列出返回的前 20 条序列和取值，确认表达式写对了再保存（语法错误会原样显示 Prometheus 的报错）。
3. 设置**比较方式**（≥ / > / ≤ / <）、**严重阈值**、可选的**警告阈值**、持续时间和通知渠道。

工作方式：

- 平台**每分钟**对适用的集群执行一次**即时查询**（`/api/v1/query`）。表达式必须返回**即时向量**（或标量）；区间向量（如 `up[5m]`）会报错，请套上 `rate()`、`avg_over_time()` 等函数。
- **返回的每条序列就是一个告警对象**，对象名取 `instance` 标签（没有 `instance` 时列出全部标签，如 `device=sda, instance=10.0.0.1:9100`）。同一规则每个集群最多处理 200 条序列。
- 表达式里的 `$sel` 会替换为集群「集群接入」里配置的 **Prometheus 选择器**（例如 `job="StarRocks_prod"`）。写法：`starrocks_be_disks_data_used_pct{$sel}`，或 `foo{$sel,type="x"}`；集群没有配置选择器时 `$sel` 连同后面的逗号一起去掉。
- 取值满足条件即告警：≥ / > 规则的警告阈值不能大于严重阈值，≤ / < 规则的警告阈值不能小于严重阈值。持续时间、合并、静默、认领、通知渠道、恢复通知与内置规则完全一致。
- **查询失败不会当作恢复**：Prometheus 连不上或表达式出错时，已有的告警保持原状，规则列表的“最近评估”显示失败原因。序列消失（对象不存在了）视为恢复；停用或删除规则后其告警立即关闭。
- 例：磁盘剩余 —— `min by (instance) (node_filesystem_avail_bytes{mountpoint="/data"} / node_filesystem_size_bytes{mountpoint="/data"}) * 100`，比较方式 ≤，警告 20、严重 10，单位 `%`。

### 静默

计划内维护时，**＋ 新建静默**（`alert.silence`）：选择集群（或全部集群，需要“全部集群”数据范围）、规则（可选）、对象包含的文本（可选）、时长（5 分钟到 30 天）和原因，到期自动失效，也可提前 **解除**。在告警行点“静默”会自动带入该告警的集群、规则和对象。被静默的告警不发送通知，**恢复通知同样不发送**。

### 通知渠道

支持 **企业微信、钉钉、飞书、Lark、Slack、通用 Webhook、邮件**（邮件经「平台设置 → 通知」中的 SMTP 发送）和 **短信**（经「平台设置 → 通知 → 短信网关」发送）。暂不支持自定义消息模板。每个渠道可选择接收的告警级别（严重 / 警告 / 提示）；**测试** 按钮发送一条测试消息，列表显示最近一次发送结果（均需 `alert.channel`）。渠道对所有集群共用，管理需要“全部集群”数据范围。

- 地址与签名密钥加密保存，页面只显示脱敏后的地址；编辑时留空表示保持不变。
- 规则里可以指定只发送到某几个渠道；不指定则发送到全部启用的渠道（再按各渠道的接收级别过滤）。删除渠道时规则里对它的引用会一并清理。

| 类型 | Webhook 地址格式 | 安全校验 |
|---|---|---|
| 飞书 | `https://open.feishu.cn/open-apis/bot/v2/hook/<token>` | 签名校验密钥 |
| Lark | `https://open.larksuite.com/open-apis/bot/v2/hook/<token>` | Signature verification |
| Slack | `https://hooks.slack.com/services/T…/B…/…` | — |
| 企业微信 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<key>` | — |
| 钉钉 | `https://oapi.dingtalk.com/robot/send?access_token=<token>` | 加签密钥（SEC 开头） |
| Webhook | 任意 HTTP(S) 地址 | HMAC 签名（可选），负载为结构化 JSON |
| 邮件 | 收件人邮箱（多个用逗号分隔） | — |
| 短信 | 手机号（多个用逗号分隔，最多 20 个） | 由平台的短信网关配置决定 |

配置步骤：

- **飞书 / Lark**：群设置 → 群机器人 → 添加「自定义机器人」→ 复制 Webhook 地址；在「安全设置」中勾选**签名校验**并把密钥填到平台（推荐）。Lark 与飞书配置方式相同，只是域名为 `open.larksuite.com`。
- **Slack**：创建 Slack App → 开启 **Incoming Webhooks** → Add New Webhook to Workspace 选择频道 → 复制 Webhook URL。一个 Webhook 只能发到一个频道。

- **短信**：先由管理员（`setting.notify`）在「平台设置 → 通知 → 短信网关」配置服务商和模板（见下），再在这里新建“短信”渠道，填写接收告警的手机号。手机号加密保存，页面只显示 `138****0000`。点渠道的**测试**按钮会真实发送一条测试短信。

> 注意：Lark、Slack 为境外服务，平台服务器需要能访问外网（可在「平台设置 → 基础」配置 HTTP 代理）。告警内容会发送到第三方平台，请勿在告警描述中包含敏感数据。

### 短信渠道

短信由「平台设置 → 通知 → 短信网关」统一发送，支持三种服务商：

| 服务商 | 需要配置 | 说明 |
|---|---|---|
| 阿里云短信 | AccessKeyId / AccessKeySecret、签名、模板 CODE、模板变量 | 调用 Dysmsapi `SendSms`（2017-05-25），国内手机号；签名写 `【数据平台】` 或 `数据平台` 均可 |
| 腾讯云短信 | SecretId / SecretKey、SdkAppId、签名、模板 ID、地域（默认 ap-guangzhou）、模板变量 | 调用 `SendSms`（2021-01-11），11 位国内号码自动补 `+86` |
| 通用 HTTP 网关 | 网关地址、鉴权 Token（可选）、签名 | 平台向网关地址 `POST` JSON：`sign`、`phones`、`content`、`title`、`level`、`template`、`params`；配置了 Token 时带请求头 `Authorization: Bearer <Token>`；HTTP 非 2xx，或返回 JSON 里的 `code` / `errcode` 不是 0 / `OK` / `success` 都视为失败 |

阿里云 / 腾讯云必须使用**审核通过的签名和模板**。「模板变量」按模板里变量出现的顺序填写，可用：`level` 级别、`cluster` 集群、`rule` 规则、`inst` 首个告警对象、`value` 首个取值、`count` 对象数、`time` 时间（HH:MM）、`status`（告警 / 恢复）。例如模板为“${cluster} 集群发生 ${level} 告警：${rule}”，则变量填 `cluster, level, rule`。每个变量值最多 20 个字，超出会截断。

通用 HTTP 网关收到的 `content` 形如 `【数据平台】【严重】prod · 节点失联：BE 10.0.0.1:8040，请登录运维平台处理`（最多约 120 字）。密钥 / Token 加密保存，页面和审计日志不显示。在短信网关配置里可以先**发送测试短信**（用表单中尚未保存的配置，密钥留空沿用已保存的）。

> 短信按条计费，告警风暴时请合理设置渠道的**接收级别**（建议短信只接收“严重”）以及「告警合并」「重复提醒」「免打扰时段」。

### 通知怎么发（发送策略）

在「平台设置 → 通知」配置，立即生效：

| 策略 | 行为 |
|---|---|
| 告警合并（N 分钟） | **同一集群、同一规则**的告警，从产生起等待 N 分钟，期间新增的合并为**一条**消息发送（0 = 立即发送，不合并）。严重告警同样遵守，如需马上通知请设为 0 |
| 重复提醒（N 分钟） | 仍在告警中、未被认领的告警，距离上次通知满 N 分钟再次提醒（0 = 不重复） |
| 恢复通知 | 告警恢复时发送一条“【已恢复】”消息（只对发送过通知的告警） |
| 免打扰时段 | 时段内（可跨零点）只发送**严重**级别，警告 / 提示不发送；时段结束后仍未恢复的告警会补发 |

- 渠道发送失败时，5 分钟后重试；所有渠道都失败的告警保持“未通知”，下一次评估继续尝试；没有任何可用渠道时告警只显示在平台里。
- 每次通知的发送结果写入「操作审计」（操作人为“系统（告警中心）”）。
- 通知内容：集群、时间、告警对象与说明，以及“查看详情”链接（需要在「平台设置 → 基础」配置访问地址）。

## 操作审计

### 平台操作审计

记录平台上每一次按钮操作：时间、用户、来源 IP、集群、菜单、**权限码**、操作内容、结果（成功 / 失败 / 拒绝 / 待复核）以及变更明细（如角色权限的增减、设置项的“旧值 → 新值”）。

- 因无权限被拒绝的尝试同样记录，结果为“拒绝”；登录成功 / 失败、退出、改密码都会记录。
- 筛选条件：账号、结果、起止日期（含当天）、关键字（操作 / 权限码 / 集群 / 执行内容）；按时间倒序，每次加载 100 条，点「加载更多」继续。
- **⇩ 导出 CSV**（`audit.export`）：按当前筛选条件导出，最多 50000 条，UTF-8 带 BOM，Excel 可直接打开；以 `=` `+` `-` `@` 开头的内容会加单引号前缀，防止 CSV 公式注入。**导出本身也会被记录。**
- **数据范围**：数据范围为“全部集群”的用户能看到全部记录；范围受限的用户只能看到范围内集群的记录和自己的操作。
- **保留期**：默认 180 天（「平台设置 → 基础」可延长，不能少于 180 天）。保留期内任何角色都不能删除；超过保留期的记录由平台每 6 小时自动清理一次。
- 密码、密钥、Webhook 地址中的 token、代理密码不会出现在审计中。

### 待复核（双人复核）

管理员在「平台设置 → 安全策略」开启 **双人复核** 后，高危操作（目前包括：移除集群、删除用户、删除角色；后续接入的高危操作同样适用）提交时不会立即执行，而是进入“待复核”：

1. 提交人看到“已提交复核”，操作记录为“待复核”。同一操作在待复核期间不能重复提交。
2. **另一位**同时拥有该操作权限码、且数据范围包含该集群的用户，在「操作审计 → 待复核」点 **批准并执行** 或 **驳回**（可填原因）。提交人不能复核自己的申请；没有该权限码的用户（例如审计员）也不能复核。
3. 批准后，平台**以提交人的身份**执行原请求，并重新校验提交人的账号状态、权限与数据范围——如果提交人此时已被锁定或收回了权限，执行会失败并给出原因，不会越权。
4. 提交人可以在批准前 **撤回**；24 小时内无人处理的申请自动失效。
5. 提交、批准、驳回、撤回、执行结果全部记录审计。

### SQL 审计

查看 StarRocks 数据库层的审计日志（AuditLoader 写入的审计表），包含所有客户端执行的 SQL、耗时、扫描行数、状态（需要 `audit.sql`）。连接平台服务时读取顶栏所选集群的审计表，可按时间范围、用户、库、状态、最小耗时、SQL 关键字筛选并分页加载，详见 [查询分析 · SQL 审计](#help/query)。

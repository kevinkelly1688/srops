# 安装部署

「安装部署」用于在一批新主机上从零安装 StarRocks 集群，并为节点扩容、升级提供主机与安装包。包括 4 个页签：**部署向导**、**部署任务**、**主机管理**、**安装包**。

## 1. 准备工作

### 1.1 主机管理（权限 `deploy.host`）

平台只保存主机的地址、SSH 用户与端口，以及探测到的规格；**主机密码不保存**。

1. 点击 **＋ 添加主机**，填写主机地址（每行一个，支持 `10.40.1.31-35` 这样的末段范围，一次最多 64 台）、SSH 端口、SSH 用户。
2. **认证方式**二选一：
   - **密码（仅首次分发公钥）**：平台用密码登录一次，把**平台公钥**写入该用户的 `~/.ssh/authorized_keys`，随后用密钥登录验证；密码用完即丢弃。
   - **平台密钥**：你已经把平台公钥加入主机（弹窗里可复制公钥）。
3. 添加成功后平台自动探测：CPU、内存、根盘大小、系统、CPU 架构（amd64 / arm64）、是否支持 AVX2、主机所在网段（用于 `priority_networks`）。
4. 勾选「免密 sudo」表示该用户可以免密 `sudo`（「一键修复环境项」需要；用 root 账号也可以）。

主机列表显示 SSH 状态、使用该主机的集群；**正被集群使用的主机不能删除**。**重新检测** 会重新连接并刷新规格。主机首次连接时记录 SSH 指纹，之后指纹变化会拒绝连接（防止中间人），主机重装后需要在平台的 `data/ssh/known_hosts` 中删除对应行。

### 1.2 安装包（权限 `deploy.pkg`）

从 StarRocks 官网下载安装包后上传：

- **StarRocks 安装包**：文件名必须是 `StarRocks-<版本>-<系统>-<amd64|arm64>.tar.gz`，如 `StarRocks-3.5.6-centos-amd64.tar.gz`。
- **JDK 包**：文件名以 `jdk`、`OpenJDK`、`amazon-corretto`、`java` 开头的 `.tar.gz`，如 `jdk-17.0.9_linux-x64_bin.tar.gz`。StarRocks 3.5 及以上需要 JDK 17。

上传时平台**边写盘边检查**：压缩包必须能正常解压，StarRocks 包必须含 `fe/bin/start_fe.sh` 与 `be/bin/start_be.sh`，JDK 包必须含 `bin/java`；同时计算 SHA256（可填写官网给出的值，不一致则拒绝）。单个文件最大 8 GB，文件保存在平台的 `data/packages/`。同名安装包不能重复上传。

**从服务器导入**（包已经在服务器上时）：点「⇩ 从服务器导入」。平台只处理两个固定目录里的文件，导入时只填文件名，不接受任意路径：

| 目录 | 用法 |
|---|---|
| `<数据目录>/import/`（如 `/opt/sr-ops/data/import/`） | 推荐。把包放到这里（例如 `wget -P /opt/sr-ops/data/import/ <官方下载地址>`），导入时校验通过后**移动**到 `packages/` 并登记，同一磁盘上是瞬间完成的 |
| `<数据目录>/packages/` | 已经手工放进去、但没有登记的文件，**原地登记**（不会移动） |

- 校验与上传完全一致：文件名格式、压缩包内容、SHA256（可选核对）；导入记录写入审计。
- 保持官方文件名，**不要解压**；最近 15 秒内仍在写入的文件（还在下载）不能导入；符号链接、目录、`.part` 临时文件会被忽略。
- 文件必须是平台服务用户（默认 `srops`）可读的：用 root 下载的文件默认是 644，可以直接读取；如果提示没有读取权限，执行 `chmod 644 <文件>`。
- 手工往 `packages/` 里放的文件，不经过「从服务器导入」是不会被平台识别的。

## 2. 环境预检与一键修复

预检是**只读**检查（`deploy.precheck`），通过 SSH 在所有目标主机上执行，检查项依据官方「部署前提条件」与「检查环境配置」：

| 检查项 | 期望 | 不满足时 |
|---|---|---|
| CPU 架构与安装包一致 | x86_64 ↔ amd64，aarch64 ↔ arm64 | 不通过 |
| CPU 支持 AVX2（amd64） | 支持 | 不通过 |
| 关闭 Swap | 没有 swap 设备 | 警告，可修复 |
| `vm.swappiness` | 0 | 警告，可修复 |
| 透明大页 THP | `madvise` 或 `never` | 警告，可修复 |
| `vm.overcommit_memory` | 1 | 警告，可修复 |
| `vm.max_map_count` | ≥ 262144 | 不通过，可修复 |
| 打开文件数 `ulimit -n` | ≥ 655350（低于 65535 不通过） | 可修复 |
| 进程数 `ulimit -u` | ≥ 65535 | 警告，可修复 |
| 与平台的时钟偏差 | 1 秒内；超过 5 秒不通过 | 手动启用 chrony / ntpd |
| 所需端口未被占用 | FE：8030 9020 9030 9010；BE / CN：8040 9050 9060 8060 | 不通过 |
| 安装目录可写 | 目录或其上级可写 | 不通过，可修复 |
| 安装目录剩余空间 | ≥ 20 GB（5 GB 以下不通过） | |
| JDK | 系统 java ≥ 17（3.5 及以上，更低版本 ≥ 8），或指定的 `JAVA_HOME` 存在 | FE 主机不通过；BE / CN 主机仅警告 |
| 免密 sudo | 可用或使用 root | 警告 |

**一键修复**（`deploy.fix`，高危，可走双人复核）在所有存在问题的主机上执行，并保存为后台任务：

- 内核参数写入 `/etc/sysctl.d/99-starrocks.conf` 并 `sysctl -p`（`swappiness`、`overcommit_memory`、`max_map_count`）；
- Swap：`swapoff -a`，并注释 `/etc/fstab` 中的 swap 行；
- THP：立即设为 `madvise`，并写入 `/etc/tmpfiles.d/starrocks-thp.conf` 开机生效；
- limits：写入 `/etc/security/limits.d/20-starrocks.conf`（`nofile`、`nproc`），**只对新登录会话生效**，已运行的进程需要重启；
- 安装目录：`sudo mkdir -p <部署目录>` 并 `sudo chown <SSH 用户>: <部署目录>`，让部署用的 SSH 用户可以写入。只处理这一个目录本身（不递归）；部署目录必须至少两级、不在 `/usr`、`/etc`、`/var` 等系统目录下，也不能是 `/home/<用户>` 本身，否则不提供修复，请手工创建并授权；目录已存在且属于 root 和 SSH 用户之外的账号时不会改动，避免影响其他服务；
- JDK：上传所选 JDK 包并解压到指定的 `JAVA_HOME` 目录（不需要 sudo，需要先有可写的安装目录，修复时会先处理安装目录）。

> 修复需要 root 账号或免密 sudo；没有权限的主机会在日志里失败并说明原因。修复完成后向导会自动重新预检。

## 3. 部署向导（5 步）

需要权限 `deploy.create` 才能使用向导；最后一步执行需要 `deploy.execute`（高危）。

### 第 1 步 · 基本信息

| 字段 | 说明 |
|---|---|
| 集群名称 | 3–64 位字母、数字、`-`、`_`，平台内唯一 |
| 环境 | 生产 / 预发 / 测试 / 开发 |
| 安装包 | 来自已上传的 StarRocks 安装包（版本与架构随之确定） |
| JDK 包 | 可选。选择后平台把 JDK 装到「部署目录/jdk」，并在 `fe.conf`、`be.conf`、`cn.conf` 写入 `JAVA_HOME`；不选则使用主机自带的 JDK |
| 部署架构 | **存算一体**（FE + BE）或 **存算分离**（FE + CN + 对象存储） |
| 部署目录 | 如 `/data/starrocks`：FE 装在 `fe/`，BE 在 `be/`，CN 在 `cn/`；FE 元数据在 `fe/meta`，BE 数据在 `be/storage` |
| root 密码 | 至少 8 位，部署时为 root 设置（部署后平台用它连接集群） |
| 对象存储（存算分离） | 存储路径、Region（必填）、Endpoint、Access Key / Secret Key（都不填则使用实例角色） |

### 第 2 步 · 主机与角色

列出 SSH 已连通的主机，勾选 FE、BE（存算分离为 CN）；FE 可再勾选 **Observer**。第一个勾选 FE（非 Observer）的主机是 **Leader**。与安装包架构不一致的主机不可选。平台提示：Leader + Follower 数量建议为奇数；BE 少于 3 台时，`default_replication_num` 会自动设为 BE 数量。

限制：所有主机的 SSH 用户与端口必须一致（部署完成后集群用同一组 SSH 信息运维）；同一台主机不能同时部署 BE 和 CN。

### 第 3 步 · 环境预检

见上一节。存在 **不通过** 项时不能进入下一步（选了 JDK 包时，JDK 项由部署过程安装，不拦截）。

### 第 4 步 · 配置确认

展示拓扑、部署步骤，以及平台会自动设置的 `fe.conf` 项：`meta_dir`、`priority_networks`（主机所在网段）、`JAVA_HOME`、`default_replication_num`，存算分离还有 `run_mode = shared_data`、`cloud_native_storage_type = S3`、`aws_s3_*` 等。你可以在两个文本框里追加 / 覆盖 `fe.conf` 与 `be.conf`（`cn.conf`）的配置，每行 `key = value`。端口使用官方默认值（FE 8030 / 9020 / 9030 / 9010，BE / CN 8040 / 9050 / 9060 / 8060）。

### 第 5 步 · 执行部署

点击 **开始部署**（需输入集群名确认；开启双人复核时需另一位同事批准后才开始）。部署在服务端后台执行，共 7 步，日志实时显示：

1. **分发安装包并生成配置**：上传安装包（校验 SHA256；主机上已有同样的文件则跳过）、解压、复制各角色目录、生成配置、创建元数据 / 数据目录，各主机并行（最多 3 台同时）；
2. **启动 Leader FE**，等待 9030 端口可连接；
3. **设置 root 密码**：`ALTER USER root IDENTIFIED BY ***`（日志中不出现密码）；
4. **其余 FE**：先 `ALTER SYSTEM ADD FOLLOWER / OBSERVER`，再 `start_fe.sh --helper <leader>:9010 --daemon`；
5. **BE / CN**：先启动，再 `ALTER SYSTEM ADD BACKEND / COMPUTE NODE`，等待存活；
6. **校验**：所有节点都已加入并存活；
7. **接入平台**：集群自动出现在「集群接入」与顶栏集群列表，SSH 信息与部署目录已填好，可直接运维。

执行过程中可以离开页面，进度在「部署任务」中查看。

## 4. 部署任务

列出部署与环境修复任务的状态、进度、发起人。**日志** 查看完整输出。

- **重试**（`deploy.execute`，高危）：任务失败或被取消后，修复问题再重试。每一步都可重复执行：已上传的安装包、已经运行的进程、已加入集群的节点都会被跳过。
- **取消**：正在执行的部署可以取消，会在当前步骤结束后停止；已写入主机的文件和已启动的进程不会被清理，重试时会接着往下做。
- 任务保存在 `data/tasks/`；平台重启时仍在执行的任务被标记为失败，可以重试。

## 5. 常见失败原因

| 现象 | 处理 |
|---|---|
| 添加主机提示 SSH 认证失败 | 密码错误，或该账号不允许密码登录；改用「平台密钥」并手工加入公钥 |
| 主机指纹与首次记录不一致 | 主机重装过；确认无误后删除平台 `data/ssh/known_hosts` 中该主机的行 |
| FE 启动后 9030 一直连不上 | 看日志末尾带出的 `fe.out` / `fe.log`；常见原因：JAVA_HOME 不对、`meta_dir` 无权限、端口被占用 |
| 其余 FE 加不进来 | 检查 `--helper` 地址、9010 端口连通性、各主机时钟偏差（< 5 秒） |
| BE 启动失败 | 检查 `storage_root_path` 目录是否存在、权限、磁盘挂载；日志会带出 `be.out` |
| 预检“端口被占用” | 该主机上已有 StarRocks 进程或其他服务，先停止或换主机 |
| 部署成功但接入平台失败 | 集群已经部署好；在「集群接入」手工导入（FE 地址、root 与密码、SSH 用户与目录） |

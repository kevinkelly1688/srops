# 平台部署与集群导入

运维平台**独立部署**，不安装在 StarRocks 集群内部，也不依赖被管理的集群。平台部署完成后是空的：管理员**导入已有集群并填写必填信息**后，才能对集群进行运维。

```
① 部署平台  →  ② 首次登录（admin，修改初始密码）  →  ③ 导入集群（填写必填信息）  →  ④ 开始运维
```

## 1. 部署平台

平台服务端是一个 Go 编写的单个二进制 `sr-ops`，自带前端页面，不依赖数据库等其他组件。

### 环境要求

| 项目 | 要求 |
|---|---|
| 服务器 | Linux x86_64 / arm64，建议 2 核 4 GB、20 GB 磁盘；生产建议独立虚拟机 |
| 元数据存储 | 平台数据目录 `data/`（文件存储：用户、集群连接信息、巡检报告、审计日志） |
| 浏览器 | Chrome / Edge / Firefox 最新版 |

### 网络要求

平台服务器需要能访问被管理集群的以下端口：

| 方向 | 端口 | 用途 |
|---|---|---|
| 平台 → FE | 9030（query_port） | 执行 SQL（SHOW / information_schema 等） |
| 平台 → FE | 8030（http_port） | 读取 FE `/metrics`（QPS、延迟、JVM） |
| 平台 → BE / CN | 8040（be_http_port） | 读取 BE / CN `/metrics`（Compaction Score 等） |
| 平台 → 所有节点主机 / 部署目标主机 | 22（SSH，端口以集群配置为准） | 系统环境巡检、节点启停、扩缩容、部署、升级、参数写入配置文件 |
| 平台 → Prometheus | 9090（可选） | 最近 60 分钟历史趋势 |
| 用户浏览器 → 平台 | 8766（或反向代理的 443） | 访问平台 |

### 一键部署脚本（推荐）

安装包里的 `install.sh` 提供安装、升级、回滚、卸载和状态查看，需要 root 与 systemd：

```
# 全新安装（解压后在安装包目录里运行）
tar xzf sr-ops-<版本>-linux-amd64.tar.gz && cd sr-ops-<版本>-linux-amd64
sudo ./install.sh install                      # 默认装到 /opt/sr-ops，监听 0.0.0.0:8766
sudo ./install.sh install --port 9000 --trusted-proxies 127.0.0.1 --https-proxy http://proxy:3128

# 升级：解压新版本安装包，在新包目录里运行
sudo ./install.sh upgrade                      # 备份 → 停止 → 替换 → 启动 → 健康检查；失败自动回滚

# 回滚到升级前的程序版本 / 查看状态 / 卸载
sudo /opt/sr-ops/install.sh rollback
sudo /opt/sr-ops/install.sh status
sudo /opt/sr-ops/install.sh uninstall          # 保留数据目录；彻底删除加 --purge
```

脚本做的事：

| 命令 | 行为 |
|---|---|
| `install` | 检查 root / systemd / 安装包架构 / 端口占用；创建系统用户 `srops`；复制程序到安装目录；生成 `sr-ops.conf` 与 systemd 服务（开机自启，带沙箱加固）；启动并等待健康检查通过；打印访问地址和初始管理员密码。已安装时拒绝重复安装（`--force` 覆盖程序文件） |
| `upgrade` | 在**新版本安装包目录**里运行。拒绝同版本和降级（`--force` 放行）；升级前把当前程序、配置和数据目录（不含 `packages/`、`tasks/`）备份到 `<安装目录>/backup/<时间>/`，只保留最近 5 份；替换程序与前端后重启，30 秒内健康检查不通过则**自动回滚**到旧版本。数据目录与 `sr-ops.conf` 原样保留。按手册手工安装的旧版本会自动从现有 unit 提取启动参数生成 `sr-ops.conf` |
| `rollback` | 把程序回滚到最近一次（或 `--to <备份目录名>`）升级前的版本，不改动数据目录；数据格式如已被新版本改动，旧版本可能无法识别，可用备份里的 `data.tgz` 恢复 |
| `uninstall` | 停止并禁用服务，删除 unit、程序和配置，**默认保留数据目录与备份**（重新安装到同一目录即可继续使用）；`--purge` 同时删除数据、备份和系统用户，需要再次输入安装目录确认 |
| `status` | 显示安装版本、监听地址、服务状态、健康检查、数据目录大小和备份列表 |

常用选项：`--dir`（安装目录）、`--port` / `--listen`、`--user`、`--trusted-proxies`、`--https-proxy`、`--no-start`、`--no-data-backup`、`--force`、`-y`（不询问）、`--no-systemd`（容器 / 测试：只复制文件）。启动参数保存在 `<安装目录>/sr-ops.conf`（`SR_LISTEN`、`SR_ARGS`、`HTTPS_PROXY`），修改后 `systemctl restart sr-ops` 生效，升级不会覆盖。

> 升级会短暂停止服务，**正在执行的后台任务（节点启停、部署、升级等）会被中断**，请确认没有进行中的任务再升级。安装目录不能放在 `/home`、`/root`、`/tmp` 下（systemd 沙箱会拦截）。

### 手工安装（不使用脚本）

```
# 1. 解压安装包（以 linux-amd64 为例）
tar xzf sr-ops-<版本>-linux-amd64.tar.gz
sudo mv sr-ops-<版本>-linux-amd64 /opt/sr-ops
sudo useradd -r -s /sbin/nologin srops && sudo mkdir -p /opt/sr-ops/data && sudo chown -R srops:srops /opt/sr-ops/data

# 2. 注册并启动服务
sudo cp /opt/sr-ops/sr-ops.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now sr-ops

# 3. 查看初始管理员密码
sudo cat /opt/sr-ops/data/initial_admin_password
```

### 首次登录

浏览器访问 `http://<平台地址>:8766/`，使用内置管理员 **admin** 和初始密码登录。**首次登录必须修改密码**（至少 10 位，含大小写字母、数字和符号），修改后初始密码文件自动删除。
- 生产环境建议在平台前面加 Nginx 等反向代理提供 HTTPS。

启动参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-listen` | `127.0.0.1:8766` | 监听地址，对外服务改为 `0.0.0.0:8766` |
| `-data` | `data` | 数据目录 |
| `-web` | `..` | 前端目录（安装包中为 `web/`） |
| `-trusted-proxies` | 空 | 可信反向代理的 IP / CIDR（逗号分隔，如 `127.0.0.1,10.0.0.0/24`）。只有来自这些地址的请求才采信 `X-Forwarded-For` 作为用户的来源 IP（用于审计与 IP 白名单）；平台前面有 Nginx 等代理时必须配置 |

### 数据目录与备份

| 文件 | 内容 |
|---|---|
| `state.json` | 用户、集群连接信息（密码已加密）、巡检规则配置、定时巡检、忽略项 |
| `reports/<集群>/` | 巡检报告（保留 90 天） |
| `audit.jsonl` | 操作审计日志（登录、导入、巡检等） |
| `secret.key` | 加密密钥。**丢失后已保存的集群密码无法解密**，务必与数据目录一起备份 |
| `ssh/` | 平台 SSH 密钥对与已信任主机指纹（`known_hosts`） |
| `packages/` | 上传的 StarRocks 安装包与 JDK 包（可能达数 GB，注意磁盘空间） |
| `tasks/` | 后台任务（节点启停、部署、扩容、升级）的日志，每个任务一个文件，最多保留最近 400 个 |

定期备份整个 `data/` 目录即可；升级时替换二进制与 `web/` 目录，保留 `data/`（用 `install.sh upgrade` 会自动完成并先备份）。

## 2. 导入集群

管理员（需要 `cluster.add` 权限）在以下任一入口点击 **导入集群**：

- 平台还没有集群时，任何集群相关页面都会显示**引导页**，点击「＋ 导入已有集群」；
- 「平台配置 → 集群接入」右上角「＋ 导入集群」。

也可以在「安装部署」中直接部署一套新集群，部署完成后会自动导入。

### 导入前准备

**运维账号**（在 StarRocks 中执行）：

```
CREATE USER 'sr_ops'@'<平台 IP>' IDENTIFIED BY '******';
GRANT NODE, OPERATE ON SYSTEM TO USER 'sr_ops'@'<平台 IP>';
GRANT SELECT ON ALL TABLES IN ALL DATABASES TO USER 'sr_ops'@'<平台 IP>';
GRANT REPOSITORY ON SYSTEM TO USER 'sr_ops'@'<平台 IP>';
GRANT CREATE RESOURCE GROUP ON SYSTEM TO USER 'sr_ops'@'<平台 IP>';
```

**SSH**：把平台公钥（「安装部署 → 主机管理」可查看）加入各节点 SSH 用户的 `~/.ssh/authorized_keys`，并确认该用户能读写 StarRocks 部署目录。

### 导入向导（5 步）

| 步骤 | 填写内容 | 是否必填 | 说明 |
|---|---|---|---|
| 1. 基本信息 | 集群名称、环境、负责人、描述 | 名称 / 环境 / 负责人必填 | 名称平台内唯一 |
| 2. FE 连接 | FE 地址（可多个）、query_port、http_port、运维账号、密码 | **必填，且必须测试通过** | 点击「测试连接并识别集群」：自动识别版本、架构（存算一体 / 存算分离）、全部 FE / BE / CN 节点，并检查运维账号权限 |
| 3. SSH 与部署目录 | SSH 用户、端口、认证方式、免密 sudo、FE 部署目录、BE / CN 部署目录 | **运维必填**，可选择“稍后填写” | 点击「测试 SSH」逐台验证连通与目录 |
| 4. 监控与审计 | Prometheus 地址、是否已安装 AuditLoader、默认告警渠道 | 可选 | 不填只影响部分功能 |
| 5. 确认导入 | — | — | 汇总信息，并列出导入后各功能是否可用 |

> 导入只建立纳管关系，**不会修改集群**。集群密码与 SSH 凭据由平台加密保存。

### 第 2 步：权限检查结果

测试连接时平台执行 `SHOW GRANTS`，逐项列出运维账号具备的权限。缺少的权限只会让对应功能不可用，例如缺少 `REPOSITORY` 时备份恢复不可用，页面会给出补充授权的 SQL。

## 3. 必填信息与“待完善”状态

| 信息 | 类别 | 缺少时的影响 |
|---|---|---|
| FE 连接 | 必填（导入时必须通过） | 无法导入 |
| SSH 凭据 + 部署目录 | **运维必填** | 集群为 **待完善** 状态：只能查看，所有运维按钮置灰 |
| Prometheus | 可选 | 趋势图、指标告警、指标类巡检项不可用 |
| 审计表（AuditLoader） | 可选 | 慢查询 Top SQL、SQL 审计不可用 |
| `REPOSITORY` 权限 | 可选 | 备份恢复不可用 |

**待完善**的集群：

- 顶栏集群列表中显示“· 待完善”；「集群接入」列表“必填信息”列显示缺少的项目。
- 进入集群相关页面时顶部有黄色提示条；运维按钮置灰并显示 🔒，悬停可看到缺少的信息。
- 查看类操作仍可使用（总览、Profile、执行计划、导出、参数对比、告警认领等）；**性能巡检**也可执行，系统环境类巡检项会显示“跳过”。
- 点击提示条中的「立即完善 →」或「集群接入」列表中的 **完善信息**，直接进入向导第 3 步补全；保存后立即解锁运维操作。

## 4. 导入后

1. 在顶栏选择集群；
2. 建议先运行一次「性能巡检」，确认集群健康状况；
3. 在「告警中心」确认告警规则与通知渠道；
4. 在「角色权限」中为相关角色的“数据范围”加入该集群（拥有“全部集群”的角色自动可见）。

## 5. 原型体验：模拟全新部署

登录页“原型演示账号”下方勾选 **模拟全新部署（无集群，仅 admin）**，用 admin 登录，即可从空平台开始体验：

1. 首次登录弹出修改密码；
2. 各集群页面显示引导页；
3. 用导入向导导入集群（第 2 步填写任意密码即可测试通过；FE 地址以 `10.6` 开头会识别为存算分离集群）；
4. 第 3 步勾选“稍后填写”可体验“待完善”只读状态，再通过「完善信息」解锁。

刷新页面后恢复为演示数据。
